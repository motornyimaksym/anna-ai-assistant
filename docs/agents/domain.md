# Domain docs

This repository has one shared booking-assistant domain. `SPEC.md` is the source of expected product behavior and functional requirements. `docs/data-model.md` describes persisted data. Related implementation and operational docs remain under `docs/`.

Before domain work, read the relevant sections of `SPEC.md` and `docs/data-model.md`, then read root `GLOSSARY.md` and `docs/adr/` decisions when those files exist. Create the glossary and ADR directory lazily when a term is settled or a hard-to-reverse architectural trade-off needs recording. Do not duplicate product requirements in those files.
